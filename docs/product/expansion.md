## 边界

- 广场（`community`）只做公开动态。助手入口在底栏「小x」，不在广场。对话、病历、经验正文都不进 `Post`。
- 助手回答里的「相近内容」只带摘要（id + 标题/正文/封面）。点进去走对方页面路由。相近帖还没接，`related_posts` 仍是 `[]`。接上之后只挂已发布帖；经验模块落地后再扩，不把经验行写进帖子表。
- 问诊需要生成文字时，只调 `assistant` 的公开 service，不在 `consult` 里再接一套模型或向量库。
- 向量库、切片、embedding、LLM、工具调用、模型密钥只放 `assistant` 服务端。小程序只打助手自己的 HTTP 合同，不选模型、不调工具。
- 跨模块只走对方公开 service；页面不 import 另一模块的 `services`（`media` 除外，见 [modules.md](../framework/modules.md)）。

## 回答流水（行为规范）

用户发一句是一次 `POST /api/v1/assistant/ask`，只看到**一条**回答。列表和消息另走 GET，不进这条流水。相关度打分、问法改写、工具调用都在 `assistant` 服务端，还没做。**改的是拿去搜知识库的问法，不是内部先生成几套答案再挑。**

不得：用「向量库有没有返回行」当失败；把不合格段落塞进生成；小程序接 LLM 或工具；工具无限轮；症状/用药走 `generated` 编诊断或药名。

### 步骤（要做成的）

1. 用用户原问题检索向量库（top-k）。几乎总会返回几段，空结果很少见。
2. **相关度门**（不是向量相似度）：每段能不能当本题证据。分三档：够用 / 含糊 / 不行。
   - **够用**：只用过线段落生成 → `source = knowledge`，带 `citations`。
   - **含糊 / 不行**：丢掉这批段落，不进入提示词。
3. 不够用时，按原问题**内部改写检索问法**（用户不可见），对**同一知识库**再搜，最多再 1～2 次。够用了仍是 `knowledge`。
4. 改写后仍不够用 → 才调 LLM，并只给有限工具（联网搜；以后可加站内经验检索）。工具最多 2 轮。
   - 工具有能用的资料 → 按资料答，`source = search`。
   - 工具也没有，且是日常常识 → 模型用自身知识答，`source = generated`。生成回答不加「仅供参考」芯片，正文也不写这四个字。
   - 工具也没有，且像看病/用药 → **拒答**：说明知识库没有、建议去医院，不编诊断、药名、剂量。
5. 相近广场帖始终附加在回答下，**不参与打分、不当证据**。

问诊若要生成文字，只调助手这一条流水，不另接一套模型。

### 现在做到哪

上面是要做成的流水，现在没有做完。用户发一句仍是一次 `POST /api/v1/assistant/ask`，只看到一条回答。POST 字段没变。历史列表 `GET /api/v1/assistant/conversation`、消息列表 `GET /api/v1/assistant/conversation/{id}/message` 已在合同里；这两条和建议、提问一样，`useMock` 为 true 时直连本机，不写 mock。`source` 仍是 `knowledge` / `search` / `generated`。看病用药在检索前固定拒答，`source` 仍为 `generated`（不新增第四档）。余弦距离门过线的块仍拼成说明书正文，`source = knowledge`。这两类都不调模型，但两轮落库，下一轮生成能看见。502 不落库。第 2 步三档、问法改写、工具都未做，运行时不会走出 `search`。`related_posts` 仍是 `[]`。`consult`、`experience` 仍未做。没命中、且不是拒答时才走补全。检索只用当前这句。一段只在用户点「新对话」时结束。补全时模型看这一整段；保险丝只截送进模型的副本（最新 60 条或约 8000 字），屏幕全文保留。`ASSISTANT_LLM` 为 `off` 或未配时仍是固定短句「我是小x。这是常识说明，仅供参考，不能代替专业意见。」这句是 200，会落库。当前取值、地址和进程见 [handoff.md](../handoff.md)。说明书 21 篇，嵌入是哈希；现有种子正文都不超过 400 字，所以一篇一块。`knowledge_answer` 仍只拼排名第一篇文章里的过线块；以这批种子来说，那就是整篇。

## 助手这一刀（页面已接）

形态已确认并落地。模块按 [adding-a-module.md](../framework/adding-a-module.md) 建在 `assistant`。

- 底栏中间 C 位「小x」仍是 tab → `modules/assistant/pages/chat/chat`。历史是非 tab 页 `modules/assistant/pages/history/history`，从对话页进去。广场不加入口。文案用「小x」，不用「问问」「养宠问答」。
- 一段对话只在用户点「新对话」时结束。冷启动空白，不自动打开最近一段。切 tab 再回来保留当前段。点「新对话」不建空会话。历史里点一段会拉回该段，并继续用那个 `conversation_id`。隔夜、换话题不自动切段。历史页时间按手机本地时区显示；合同 `updated_at` 仍是 UTC，带 `Z`。微信里这条历史流程还没点验。
- 对话页：空态问候 + 推荐问题；对话气泡；来源芯片；命中说明书时挂引用；下面最多 2 条相近广场帖（接口里 `related_posts` 仍是 `[]`）。
- 阶段 F：mock 用关键词假装 `knowledge` / `search` / `generated`。当时不接真向量库、不接搜索工具、不建 `consult` / `experience`。现在建议、提问、历史列表、消息列表不走那套 mock。
- 服务端距离门和切块已接：过线仍是余弦距离，`answer` 由过线块拼出，不调模型。第 2 步三档、改写、工具仍未做。没命中且不是拒答才走补全。小程序的建议、提问、历史列表、消息列表打本机 API，不写 mock；进程不在听就打不出去。其余仍 mock。开关和启动见 [handoff.md](../handoff.md)。
- 唯一步已接上的模型行为：检索没有过线块、且不是拒答时，由补全写 `generated`，并看这一整段。保险丝只截送进模型的副本（最新 60 条或约 8000 字），屏幕全文保留。过线直接回说明书正文，不调模型。看病用药在检索前就固定拒答，到不了补全。开关是服务端 `ASSISTANT_LLM`（`off` | `xai` | `openai`），只活在 `assistant` 模块。小程序不选模型、不持密钥。`off` 或未配时仍是上面那句固定短句。`xai` 仍是官方 Responses API，不是当前取值。`openai` 走 OpenAI 兼容 `chat/completions`。取值、地址、模型名、超时和启动命令只写在 [handoff.md](../handoff.md)。密钥只在 gitignore 的 `server/.env`。选了提供方但密钥、地址或模型为空时，接口回「请稍后再试」，不假装已经答了。
- 助手是站内通用问答，不限于宠物百科。生成回答气泡仍不显示「仅供参考」。`knowledge` 仍显示「说明书」，`search` 仍显示「检索」。等待文案是「正在思考...」。人设仍是口语、两三句。有更早对话就顺着接，不要每句复述，也不要用「我是小x。这是常识说明」开头。诊断、药名、剂量、正文「仅供参考」仍禁止。`off` 或空时的固定短句正文仍有「仅供参考」，那句没改。开药、下诊断留给 `consult`，第一刀不做问诊表单。
- 图生视频不占底栏，从首页四入口进创作页。
