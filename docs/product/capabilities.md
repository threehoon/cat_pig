# 能力清单

能力按簇划分。英文模块名已锁定，见 [handoff.md](../handoff.md)。落地时用 [adding-a-module.md](../framework/adding-a-module.md)。阶段 F 只建小程序目录；后端同名目录后补。

对标范围以 [benchmark.md](benchmark.md) 为准：截图里有的 **全部要做**。本文件只排实现顺序和模块边界。

## 优先级

- **P0**：没有则「内容小程序」不成立。阶段 F 把 P0+P1 **页面和 mock 一起铺上**（必须走各模块 `services/`，见 [handoff.md](../handoff.md)）；接真数据时仍先打通 P0。
- **P1**：积分、签到、关注、审核状态、点赞 / 评论 / 收藏 / 转发。阶段 F 要有对应页；扣积分 / 真审核放到接 API 之后。
- **P2**：图生视频 **真出片**（异步 worker）。阶段 F 只要创作页和生成记录能点；结果用占位。
- 未列入 benchmark 的：未改文档前当作需求不存在。

## P0 — 主路径（门户 + 相册 + 广场）

| 能力簇 | 要做到 | 模块目录 |
|---|---|---|
| 登录与用户 | 微信登录、JWT；「我的」展示昵称头像 | `auth`、`me` |
| 媒体 | 选图上传、存 URL | `media` |
| 首页 | 顶图占位、四个入口、推荐帖预览 | `community`（页面 `home`） |
| 相册 | 列表；上传（多图、标题、说明、标签、可见性三档、同步广场开关） | `album` |
| 广场 / 论坛 | 搜索、推荐 / 关注、大家都在看、帖子列表、详情、发动态 / 草稿 | `community` |
| 创作入口 | 图生视频表单页（先不真出片） | `video` |
| 我的 | 入口：我的发布、收藏、相册、关注、粉丝、积分明细、积分任务、生成记录、设置；资料卡展示动态 / 获赞 / 关注 / 粉丝 | `me` |

P0 主路径（必须能演示）：

登录 → 首页四个入口能跳 → 上传一组相册 → 发一条动态并在广场推荐看到 → 打开创作页填素材（提交后生成记录多一条占位）。

依赖：相册 / 帖子 / 视频都通过 `media` 的 URL 引用图。帖子不引用相册表结构（同步论坛是发帖时带上图，不是 join 相册行）。

## P1 — 社区与积分

| 能力簇 | 要做到 | 模块目录 |
|---|---|---|
| 我的发布 | 按已发布 / 审核中 / 未通过 / 草稿筛选；编辑删除 | `community` |
| 关注 | 详情页关注作者；广场「关注」流 | `community` |
| 帖子互动 | 点赞、评论、收藏、转发；点赞和收藏可同时点 | `community` |
| 积分流水 | 余额、获取 / 消耗、按时间筛选、规则说明；发帖 / 评论 / 点赞给分 | `points` |
| 每日签到 | 首页入口进独立签到页（月历、补签卡）；每天一次；连续天数；第 3 / 7 天额外积分和补签卡；补签 | `points` |

发帖成功给积分（每天前 3 条）、评论每天 1 条、点赞每天 3 条、生成视频扣积分：由 `points` 的公开 service 被 `community` / `video` 调用，不把积分表写进那两个模块。补签卡和连续天数只进 `points`。签到不进积分任务页。

## P2 — 真出片

| 能力簇 | 要做到 | 模块目录 |
|---|---|---|
| 视频任务 | 2–9 图、提示词、分辨率；状态 pending / running / success / failed | `video` |
| 出片 worker | 异步生成，不阻塞 FastAPI 进程 | 内核 worker，不进小程序 |

小程序只：提交任务、拉列表、看状态 / 结果 URL。密钥和模型只放服务端。

## Agent 实现时

1. 先读 [positioning.md](positioning.md) 和 [benchmark.md](benchmark.md)，再读本文件。
2. 一次只加一个能力簇，按 [adding-a-module.md](../framework/adding-a-module.md)。
3. 积分不要写进 `community` / `video` 的 `models.py`；视频任务不要写进 `points`。
4. 禁止为了长得像对标截图去改 `core`，禁止使用对方品牌名与插画。
