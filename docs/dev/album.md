## 已定

相册是 **一组 1–9 张的图集**（标题、说明、标签、封面），不是云图库，不是按宠物分册。

| 点 | 决定 |
|---|---|
| 相册 tab | 自己的管理页：管理 + 展示自己的全部相册（含私密） |
| 别人的相册 | 后期。从别人的内容点进去看「他的相册」。本文件不做入口 |
| 好友 | 互相关注才能看「好友可见」 |
| 看别人时 | 只能看到公开 + 好友可见（互关时）。私密永不出现 |
| 黑名单 | 后期。拉黑优先：公开也对被拉黑人不可见；同时盖相册和广场动态 |

### 可见性

界面文案：公开 / 私密 / 好友可见。字段（切片 4 才进合同）：`visibility: "public" | "private" | "friends"`。省略视为 `private`。新建默认私密。

| 观看者 | 公开 | 好友可见 | 私密 |
|---|---|---|---|
| 主人（相册 tab / 自己的详情） | 可见、可改、可删 | 同左 | 同左 |
| 互相关注 | 可见 | 可见 | 不可见，当不存在 |
| 单向关注 / 路人 | 可见 | 不可见，当不存在 | 不可见，当不存在 |
| 已被拉黑（后期） | 不可见 | 不可见 | 不可见 |

硬规则：

1. `GET /api/v1/album` 永远只返回当前用户自己的，三档全返回。这是管理列表，不是发现流。
2. 看别人（后期）另开路径，例如 `GET /api/v1/album?user_id=`，按上表过滤。无权时列表不出现该本；详情 `NOT_FOUND`（不用 `FORBIDDEN`，避免暴露私密存在）。
3. 相册 tab 不做发现子栏，不灌别人的图集。
4. 本阶段只有公开可以同步到广场。好友可见、私密禁止 `sync_to_forum: true`。广场帖还没有可见性，好友可见若同步会进推荐流。
5. 私密可以改成公开或好友可见。已同步的公开相册禁止改成非公开（`VALIDATION`）。广场帖本阶段不能收回。
6. `can_view(viewer, album)` 是 album 模块里的单一纯函数。管理列表不用它过滤。黑名单以后只在这个函数里加「拉黑则 false」。切片 4 写好函数；看别人的接口本文件不加。

## 排版

气质：`docs/miniprogram/visual.md` 的 token。页面 scss 只写这一页。Skyline：flex，不用 grid；纵向 `scroll-view type="list"`。原生 switch `color` 仍 `#F0783C`。

对标截图 `docs/product/reference/03-album-points-tasks.png` 只有上传页。学结构，不抄品牌、插画、文案原句。预设标签保持合同：`写真` `美食` `生活` `温馨` `风景`。

### 列表 L3（切片 2 出卡，切片 4 出分档和角标）

```
  [全部] [公开] [好友可见] [私密]

[ 封面 + 可见性角标 ]  [ 封面 + 可见性角标 ]
  标题                    标题
  n 张 · 日期              n 张 · 日期
  标签                     标签
                         [上传]
```

- 分档只筛自己的列表，前端做。`GET /api/v1/album` 不为此加 query。
- 日期：同年 `M月D日`，跨年 `YYYY年M月D日`。
- 点卡：切片 2 仍进编辑；切片 3 起进详情。卡上不叠菜单。
- FAB「上传」。空库用现有 `empty-state`。分档筛空：文案「这个分类还没有相册」，不要「去上传」。

### 详情 D1（切片 3）

大封面（`cover_url`）→ 全部图横滑缩略图（封面有标记）→ 点图 `wx.previewImage` → 标题、说明、标签、时间（切片 4 加可见性）→ 编辑 / 删除。

编辑进 `upload?id=`。删除确认后 `DELETE` 并 `navigateBack`。不做点赞评论。

### 上传 V1（切片 1 对标，切片 4 加可见性）

顺序：选图 → 标题必填 → 说明必填 → 标签（预设 + 自定义）→ 可见性三芯片（切片 4）→ 同步到广场 → 保存。编辑态标题「编辑相册」，多「删除相册」。

选图：点缩略图预览，右上角删除；封面角标；点非封面设为封面；默认首图；虚线「添加照片」；最多 9 张。提交带 `cover_url`。

可见性三芯片样式跟标签。非公开时同步开关关闭且禁用，`sync_to_forum` 强制 `false`。仅公开可开同步。开关下写明这一点。

## 切片 4 — 可见性

**做完标准：** 点验清单 6 条用户都点过，合同已含 `visibility`，且 `npm run typecheck` 通过。用户说「切片 4 过了」。

先改合同，再改代码。禁止先改页面再补字段。

### 4a 合同

`docs/api/contract.md` 的 Album 增加 `visibility`，值为 `"public"` / `"private"` / `"friends"`。请求可省略，省略 = `private`。`POST` / `PATCH` 可带。

写进合同的规则：

- 仅 `visibility === "public"` 允许 `sync_to_forum: true`。其它值带 true → `VALIDATION`。
- 已是公开且 `sync_to_forum: true` 的相册，`PATCH` 把 `visibility` 改成非公开 → `VALIDATION`。

本片同时改 `docs/product/benchmark.md`：相册那一行补「可见性三档（公开 / 好友可见 / 私密）」；别人的相册仍不列为现有能力。

不加 `GET /album?user_id=`。

### 4b 代码

改：`miniprogram/modules/album/types/album.ts`、`services/mock.ts`、`pages/upload/`、`pages/list/`、`pages/detail/`、`miniprogram/mocks/store.ts`。`can_view` 放 album 模块内纯函数（例如 `modules/album/visibility.ts`）。

做：

- 上传：V1 三芯片；新建默认私密；非公开禁用同步。
- 列表：卡上可见性角标；顶部分档芯片，前端筛；筛空文案「这个分类还没有相册」。
- 详情：露出可见性。

4. 分档「全部」能看到自己的全部。筛空时文案「这个分类还没有相册」，没有「去上传」。
